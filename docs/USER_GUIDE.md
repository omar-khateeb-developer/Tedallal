# دليل الاستخدام الشامل ونظام الصلاحيات لنظام تدلّل (Tedallal MVP Guide)

نظام **تدلّل (Tedallal)** هو منصة رقمية متكاملة للمطاعم والمقاهي تتيح للزبائن الطلب المباشر من الطاولة عبر مسح رمز الـ QR بدون الحاجة لتنزيل تطبيقات، مع لوحة تحكم فورية لطاقم المطبخ والإدارة.

---

## 👥 1. الممثلون والصلاحيات في النظام (Actors & Permissions)

يحتوي النظام على 3 فئات من الممثلين (Actors) الرئيسية، لكل منها صلاحيات ونطاق عمل محدد لحماية أمان وتكامل البيانات:

### 1️⃣ الزبون (Customer / Table Guest)
* **وسيلة التوثيق**: توكن الجلسة المؤقت (`ValidateTableSession` middleware) المقترن بطاولة محددة عبر `public_token`.
* **الصلاحيات (Permissions)**:
  - 🟢 مسح رمز الـ QR والدخول لقائمة الطعام الخاصة بالطاولة (`GET /t/{public_token}`).
  - 🟢 استعراض تصنيفات المنيو والأصناف المتاحة والأسعار.
  - 🟢 إنشاء وإدارة سلة التسوق الخاصة بالطاولة (إضافة الأصناف، تعديل الكميات، إضافة ملاحظات خاصة على الأصناف).
  - 🟢 إرسال وتأكيد الطلب (`POST /api/public/orders`).
  - 🟢 تتبع حالة الطلب فورياً في الوقت الفعلي (`GET /api/public/orders/{orderNumber}`).
* **القيود والمحذورات (Restrictions)**:
  - 🔴 لا يستطيع الوصول لأي شاشات إدارية أو لوحة المطبخ.
  - 🔴 لا يستطيع رؤية أو التعديل على طلبات الطاولات الأخرى.
  - 🔴 لا يستطيع التلاعب بأسعار الأصناف (يتم حفظ لقطة السعر لحظة الطلب في السيرفر).

---

### 2️⃣ موظف الخدمة / المطبخ (Staff / Kitchen Worker)
* **وسيلة التوثيق**: حساب مصدق (`auth:sanctum` / `session`) يحمل دور `UserRole::Staff`.
* **الصلاحيات (Permissions)**:
  - 🟢 تسجيل الدخول عبر شاشة `/login`.
  - 🟢 الوصول للشاشة الحية لطلبات المطبخ والخدمة (`/staff/orders`).
  - 🟢 رؤية كافة الطلبات الواردة من جميع طاولات المطعم في الوقت الفعلي.
  - 🟢 التبديل بين حالات الطلب: (قيد الانتظار ⏳ -> قيد التحضير 👨‍🍳 -> جاهز للتقديم 🍽️ -> مكتمل ✅ -> ملغى ❌).
  - 🟢 الاطلاع على إحصائيات اللوحة السريعة.
  - 🟢 تعديل الملف الشخصي والبريد الإلكتروني الخاص به.
* **القيود والمحذورات (Restrictions)**:
  - 🔴 لا يستطيع إضافة، تعديل، أو حذف الطاولات أو إعادة توليد رموز الـ QR.
  - 🔴 لا يستطيع تعديل أصناف المنيو، التصنيفات، أو الأسعار.
  - 🔴 لا يستطيع تعديل إعدادات المطعم العامة.
  - 🔴 لا يستطيع إدارة أو إضافة مستخدمين آخرين.

---

### 3️⃣ مدير النظام / صاحب المطعم (Admin)
* **وسيلة التوثيق**: حساب مصدق (`auth:sanctum` / `session`) يحمل دور `UserRole::Admin`.
* **الصلاحيات (Permissions)**: **وصول كامل وشامل لجميع أجزاء النظام (Full Control)**
  - 🟢 جميع صلاحيات الموظف (Staff) في متابعة وتحديث الطلبات.
  - 🟢 الاطلاع على لوحة الإحصائيات المتقدمة والمبيعات الإجمالية والتحليلات (`/admin/dashboard`).
  - 🟢 **إدارة الطاولات**: إنشاء طاولات جديدة، تعديل أسمائها، حذفها، إعادة توليد الـ QR Token لأمان الطاولة، وتنزيل أو طباعة الـ QR مجمعاً (`/admin/tables`).
  - 🟢 **إدارة المنيو**: إضافة وتعديل وحذف تصنيفات المنيو وأصناف الوجبات والأسعار والصور والتوافر.
  - 🟢 **إعدادات المطعم**: تعديل اسم المطعم، الهاتف، العنوان، والعملة (`/admin/settings`).
  - 🟢 **إدارة طاقم العمل**: إنشاء حسابات جديدة للمدراء والموظفين، تعديل الأدوار، تعطيل أو حذف الحسابات (`/admin/users`).

## 🔑 2. بيانات تسجيل الدخول الافتراضية (Default Credentials)

عند تشغيل أمر البذر `php artisan migrate:fresh --seed` يتم إنشاء الحسابات التالية:

| الحساب | البريد الإلكتروني (Email) | كلمة المرور (Password) | الصلاحيات (Role) |
| :--- | :--- | :--- | :--- |
| **مدير النظام** | `admin@tedallal.test` | `password` | **Admin** (وصول كامل) |
| **موظف المطبخ/الخدمة** | `staff@tedallal.test` | `password` | **Staff** (متابعة وتحديث الطلبات) |

## 📱 3. حالات استخدام الزبون (Customer Use Cases)

### **UC-01: مسح رمز الـ QR والوصول للطاولة**
* **الرابط**: `http://localhost:8000/t/{public_token}`
* مسح رمز الـ QR ينشئ جلسة طاولة مؤقتة وآمنة وتفتح قائمة المنيو المباشرة.

### **UC-02: تصفح القائمة والفلترة**
* تصفح الأصناف والتصنيفات والأسعار باللغة العربية مع دعم RTL.

### **UC-03: إدارة سلة التسوق**
* إضافة الأصناف، تعديل الكمية، وتخصيص كل صنف بملاحظات خاصة (مثل: "بدون سكر").

### **UC-04: تأكيد الطلب**
* مراجعة الإجمالي وإرسال الطلب وحفظ لقطة من الأسعار (Price Isolation).

### **UC-05: تتبع حالة الطلب الفورية**
* تتبع مراحل الطلب مباشرة (pending -> preparing -> ready -> completed -> cancelled).

---

## 👨‍🍳 4. حالات استخدام الموظف (Staff Use Cases)

### **UC-06: تسجيل الدخول وتلقي الطلبات**
* تسجيل الدخول عبر `/login` والتوجيه التلقائي لشاشة المطبخ `/staff/orders`.

### **UC-07: تحديث حالة الطلبات**
* متابعة الطلبات الحية وتحديث حالتها بنقرة واحدة مع إشعار الزبون فورياً.

---

## ⚙️ 5. حالات استخدام المدير (Admin Use Cases)

* **UC-08: متابعة الإحصائيات والمبيعات**: عبر لوحة `/admin/dashboard`.
* **UC-09: إدارة الطاولات والـ QR للطباعة**: إضافة/تعديل/حذف الطاولات وطباعتها مجمعة من `/admin/tables`.
* **UC-10: إدارة تصنيفات المنيو**: إضافة وتعديل وترتيب التصنيفات من `/admin/menu/categories`.
* **UC-11: إدارة الوجبات والأصناف**: إضافة وتعديل الوجبات والأسعار من `/admin/menu/items`.
* **UC-12: إعدادات المطعم**: تعديل الاسم والعملة والهاتف من `/admin/settings`.
* **UC-13: إدارة حسابات الموظفين**: إضافة حسابات staff و admin وتعديلها من `/admin/users`.
